# ADR-03: Off-Main-Thread `AudioWorklet` PCM Capture, Mutable Timeline & Post-Encode Pipeline

- **Status:** Accepted
- **Date:** 2026-11-19
- **Related CUJs:** [CUJ-02](../cuj/CUJ-02-core-recording.md), [CUJ-03](../cuj/CUJ-03-scrub-preview-punchin.md), [CUJ-07](../cuj/CUJ-07-quality-and-devices.md), [CUJ-08](../cuj/CUJ-08-draft-recovery-drive-pwa.md), [CUJ-10](../cuj/CUJ-10-local-master-export-compare.md)

## Context
StoryTape requires pause/resume, drag-to-scrub preview playback, punch-in re-recording, contextual **Stop here** tail trimming, 1-step undo, configurable high-ceiling output formats (AAC M4A, Opus WebM, lossless 16/24/32-bit WAV up to 96 kHz), optional full-resolution local master archival, and offline multi-bitrate re-encoding / blind A/B comparison. Standard `MediaRecorder` outputs opaque compressed streams that cannot be frame-accurately scrubbed, spliced without audible clicks, or undone cleanly across pause/resume sessions. Furthermore, `ScriptProcessorNode` is deprecated and causes audio glitches on the main thread.

## Decision
Adopt a **two-stage PCM capture → post-recording encode & client-side transcode** architecture in [`src/audio/`](../src/audio/) and [`public/audio/pcm-capture-worklet.js`](../public/audio/pcm-capture-worklet.js):
- **Off-main-thread capture (`AudioWorklet`)**: Capture interleaved float32 PCM frames inside `pcm-capture-worklet.js` with a ~25ms flush cadence and 50 waveform peaks/second.
- **Cross-browser low-latency hardware-clock pull-graph invariant (Android AAudio + iOS WebKit + Chromium `SilentSinkSuspender`)**: Instantiate `AudioContext` with `latencyHint: 'interactive'` (never `'playback'`) so Android Chrome uses AAudio's low-latency real-time path (`AAUDIO_PERFORMANCE_MODE_LOW_LATENCY`) with steady 4–8ms callbacks rather than AudioFlinger's power-saving mixer (whose irregular 40–100+ ms bursts underrun `MediaStreamAudioSourceNode`'s mic FIFO into 20–60ms zero dropouts and cause bursty waveform chunk arrivals). Align `getUserMedia` ideal `sampleRate` to `ctx.sampleRate` to avoid live rate-conversion bridges. Instantiate `AudioWorkletNode` with `numberOfOutputs: 1` and emit an inaudible ultrasonic Nyquist keepalive (`±1e-5` / `-100 dBFS` alternating at `sampleRate / 2`, zero DC offset, never copying mic audio to outputs) routed through `GainNode(1)` → `ctx.destination` while actively capturing. This simultaneously pulls render quanta on iOS Safari WebKit and prevents Chromium's 30-second `SilentSinkSuspender` from switching to `FakeAudioWorker` (which otherwise drifts against the capture thread and drops 10ms / 480-sample FIFO frames). Guard `ctx.audioWorklet.addModule()` per `AudioContext` so re-resuming never reloads the module.
- **Cross-browser auto-gain parity & extended studio input strip (`src/audio/inputStrip.ts`, `src/audio/audioDevices.ts`, `src/audio/nativeEncoder.ts`)**: Safari / iOS WebKit ignores `getUserMedia` `autoGainControl` and `noiseSuppression` constraints and routes `echoCancellation: false` through Apple's raw `RemoteIO` capsule (typically `-45` to `-30 dBFS` on normal speech, 20–30 dB quieter than Android Chrome with native AGC). To preserve full-band non-telephony warmth without forcing iOS `VoiceProcessingIO` (`echoCancellation: true`), `acquireMicStream` detects whether native browser/OS AGC is active (`detectNativeAgcActive`). Whenever `quality.autoGainControl` is enabled and native AGC is absent, `buildStudioInputStrip` engages a speech-gated `SoftwareAutoGainController` (`GainNode` placed ahead of the safety limiter, starting at `+12 dB`, targeting `-18 dBFS` narration RMS up to `+24 dB` max, with an adaptive room-noise floor gate so silence never pumps room hiss and fast attack on peaks above `-2.8 dBFS`). To keep real-time WebKit/Chromium `AudioParamTimeline` overhead strictly O(1), `updateAutoGain` skips no-op writes when gain delta is `< 0.002` and cancels superseded scheduled automation events (`cancelAndHoldAtTime`, or `cancelScheduledValues` + `setValueAtTime(prevAppliedGain, now)` so browsers without `cancelAndHoldAtTime` never snap back to intrinsic `param.value`) before scheduling `setTargetAtTime`. Manual `inputGain` supports `-6 dB` to `+24 dB` (`0.5×`–`15.85×`) so fixed-gain modes (`Studio Raw`, `Master Archival WAV`) can cleanly drive quiet iPhone or external dynamic mics. When `softLimiter` is enabled, follow `DynamicsCompressorNode` (which carries automatic makeup gain in Chromium/WebKit) with a lightweight C¹-continuous `WaveShaperNode` soft-clipping ceiling (`oversample = 'none'` to avoid real-time 2× FIR filter CPU overhead on mobile audio threads; exact identity below `-3 dBFS`, saturating smoothly at `-1.0 dBFS`). Apply a transparent `-1.0 dBFS` peak ceiling after resampling before compressed AAC/Opus and 16/24-bit integer WAV encoding (while leaving 32-bit IEEE Float archival WAV untouched).
- **Mutable `PcmTimeline` ([`src/audio/pcmTimeline.ts`](../src/audio/pcmTimeline.ts))**: Maintain captured audio as contiguous PCM chunks supporting exact frame-level truncation (`truncateAtFrame`), automatic **15ms raised-cosine anti-click fade-out + next-append fade-in** on both destructive cuts and plain Pause/Resume boundaries (`markPauseBoundary`), and a deep **1-step undo snapshot** shared by both punch-in re-recording and **Stop here** (`RecordingEngine.trimToPlayhead()`). Periodic crash-safe draft flushes (every 5 seconds, plus immediate flush on pause/hide/interruption) commit both the PCM chunk and draft metadata in a single atomic IndexedDB `readwrite` transaction (`saveDraftChunkAndMeta`) to minimize main-thread/disk fsync overhead during live capture.
- **Decoupled lifecycle in `RecordingEngine` ([`src/audio/recordingEngine.ts`](../src/audio/recordingEngine.ts))**: Keep React listener subscriptions strictly separate from draft-loading effects; never clear active UI listeners inside async `dispose()`.
- **Interruption recovery & opt-in iOS lock-screen capture keepalive ([`src/audio/backgroundCaptureKeepalive.ts`](../src/audio/backgroundCaptureKeepalive.ts), [`src/audio/recordingEngine.ts`](../src/audio/recordingEngine.ts))**: Playing a looping `<audio>` element simultaneously with `getUserMedia` + `AudioContext` under forced `navigator.audioSession.type = 'play-and-record'` can introduce OS audio-session contention, sample-rate mixing overhead, and choppy mic capture on iOS, Bluetooth headsets, and CPU-constrained devices. Therefore, `BackgroundCaptureKeepalive` is **opt-in and OFF by default** (`settings.backgroundRecordingKeepalive = false`), exposed as an explicit toggle under **Studio Settings → App**. When opted in, `BackgroundCaptureKeepalive.startSync()` synchronously cycles `navigator.audioSession.type` to `'play-and-record'` (defeating WebKit Bug #323104), plays the inaudible looping keepalive `<audio>`, and publishes recording `mediaSession` metadata; on pause/stop it restores `'playback'` → `'auto'`. Regardless of the toggle, zero-overhead passive resilience guards always run: `AudioContext` `statechange` (`'interrupted'`/`'suspended'` auto-resume), `document` `visibilitychange` (immediate draft persistence on `hidden`), and `MediaStreamTrack` `mute`/`ended` handling (clean auto-pause with zero lost audio and an explanatory warning banner if the OS forcibly ends the mic track). Recording Studio also provides a one-tap pure-black OLED **Blackout screen** shield (double-tap to wake) paired with Wake Lock as the recommended glitch-free dark-room recording workflow.
- **Post-recording dual-output encoding ([`src/audio/nativeEncoder.ts`](../src/audio/nativeEncoder.ts), [`src/audio/aacEsds.ts`](../src/audio/aacEsds.ts), [`src/audio/wavEncoder.ts`](../src/audio/wavEncoder.ts), [`src/audio/qualityPresets.ts`](../src/audio/qualityPresets.ts))**: Encode the final PCM timeline on Save via WebCodecs (`AudioEncoder`) + `mp4-muxer` (M4A AAC) or `webm-muxer` (WebM Opus), with automatic fallback to lossless 16/24/32-bit WAV. Normalize `AudioEncoder` AAC `meta.decoderConfig.description` through `normalizeAacDecoderDescription()` before `mp4-muxer` muxing to work around WebKit Bug #302253 (iOS 26 Safari emitting a full 39-byte `esds` descriptor instead of the raw 2-byte ISO 14496-3 `AudioSpecificConfig`, which otherwise produces a double-wrapped `esds` box rejected by AVFoundation). Under `format: 'auto'`, never select or fall back to a compressed container (such as `audio/webm;codecs=opus` on Safari/iOS) that the current browser's `HTMLAudioElement.canPlayType()` reports as unplayable; fall back to playable WAV instead. When `keepLocalMaster` is enabled, simultaneously serialize the raw un-resampled float32 timeline as a 32-bit IEEE Float WAV master (`formatTag = 3`) for local archival.
- **Pure-TS WAV decode & client-side re-encode ([`src/audio/audioExporter.ts`](../src/audio/audioExporter.ts))**: Parse 16-bit PCM, 24-bit PCM, and 32-bit IEEE Float RIFF/WAVE blobs directly in TypeScript (zero browser decoder loss/resampling) with `AudioContext.decodeAudioData` fallback for compressed inputs (automatically repairing legacy double-wrapped `esds` MP4 inputs prior to decode), then re-encode via `encodeAudio` for single/batch export and Web Audio A/B comparison playback (`AbComparePlayer`, stopping the active sample and restarting the newly selected sample from the beginning).

## System Invariants
1. **PCM capture stays off the main thread on a low-latency locked hardware clock**: `public/audio/pcm-capture-worklet.js` emits an inaudible ultrasonic Nyquist keepalive (`±1e-5`, zero mic loopback) to `ctx.destination` while active (and silence when inactive) on a `latencyHint: 'interactive'` (never `'playback'`) `AudioContext` whose `sampleRate` matches the capture stream request.
2. **All timeline boundaries are click-free**: Both destructive cuts (`punchInFromPlayhead`, `trimToPlayhead`, with 1-step undo) and plain `pause` → `startOrResumeFromEnd` boundaries apply a 15ms raised-cosine tail fade-out and arm a 15ms fade-in for subsequent frames.
3. **True-peak clipping protection & O(1) cross-browser auto-gain parity**: Active `softLimiter` caps real-time transients smoothly at `-1.0 dBFS` with `WaveShaperNode.oversample = 'none'`, `nativeEncoder` bounds post-resample peaks before lossy AAC/Opus and integer PCM WAV output (never altering 32-bit Float masters), and `SoftwareAutoGainController` activates automatically in both `RecordingEngine` and `MicLevelTester` whenever `autoGainControl` is requested on a browser/track lacking native AGC (skipping unchanged writes and cancelling prior scheduled automation events cleanly without resetting to intrinsic `param.value` so `AudioParamTimeline` stays O(1) without gain clicks).
4. **Synchronous gesture activation & opt-in background keepalive**: `AudioContext.resume()` is triggered synchronously inside user tap handlers; `BackgroundCaptureKeepalive.startSync()` runs synchronously **only** when the user explicitly opts in via `settings.backgroundRecordingKeepalive === true` (default `false`), preventing unnecessary `<audio>` + `audioSession` contention during normal recording.
5. **Listener safety**: Async engine teardown/draft reloads must never detach active UI subscribers.
6. **Lossless master fidelity**: Local masters preserve exact captured sample rate, channel count, and 32-bit IEEE Float precision without resampling or lossy round-trips.
7. **Playable & spec-compliant encoded containers**: `nativeEncoder` unwraps ESDS-wrapped WebKit AAC `decoderConfig.description` payloads into raw ISO 14496-3 `AudioSpecificConfig` bytes prior to `mp4-muxer` muxing, and `format: 'auto'` never falls back to a compressed container that the host browser cannot play back.
8. **Background / interruption safety**: Active recordings flush pending PCM chunks atomically (`saveDraftChunkAndMeta`) on periodic flushes, `visibilitychange` (`hidden`), `AudioContext` interruption, or track mute/end, auto-resume recoverable interruptions, and cleanly auto-pause (preserving all captured audio and surfacing a clear warning) if the OS permanently terminates the microphone track.

## Consequences & Trade-offs
- **Pros:** Glitch-free multi-minute recordings in Chromium/Android/iOS without 30s silent-sink clock drift, zero-clipping loudness headroom, click-free pause/resume and punch-in splices, instant 1-step undo, lossless WAV and high-bitrate AAC/Opus from a single capture pipeline, and bit-exact offline bitrate comparison directly from the captured master.
- **Cons:** Long chapters consume linear RAM for float32 PCM during active recording (mitigated by chapter-length sessions and incremental draft persistence); keeping the output sink active during recording uses marginally more battery while actively recording (silenced immediately on pause/stop).
