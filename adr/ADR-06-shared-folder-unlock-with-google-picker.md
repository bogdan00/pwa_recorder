# ADR-06: Multi-User Shared Folder Onboarding, Request Access Handoff & Pull-Mirrored Imports

- **Status:** Accepted (Amended 2026-11-22: full `drive` scope + opt-in sharing of existing personal books on join)
- **Date:** 2026-11-20
- **Related CUJs:** [CUJ-09](../cuj/CUJ-09-multi-user-sharing.md)

## Context
Multi-user audiobook sharing requires zero-backend onboarding via invite links, safe handling when a recipient does not yet have Drive permission (`403`/`404`), and clear boundaries between a user's pre-existing personal recordings and a newly joined shared family library. In addition, StoryTape originally used Google Drive's `drive.file` scope with Google Picker folder selection, but real-device diagnostics proved `drive.file` is non-recursive on shared folders (listing children inside a shared folder returned `[]` for files created by another user).

## Decision
Use full `https://www.googleapis.com/auth/drive` scope ([ADR-05](./ADR-05-client-side-drive-oauth-and-conflict-safe-sync.md)) for recursive multi-user folder access while preserving guided sharing, Request Access handoff, optional Google Picker browsing, and pull-mirrored book imports:
- **In-app Drive Permissions & Pending Access Requests management ([`src/components/ShareSheet.tsx`](../src/components/ShareSheet.tsx), [`src/drive/driveClient.ts`](../src/drive/driveClient.ts))**: Allow hosts to invite collaborators by email (`writer` for Co-Narrators, `reader` for Listeners), toggle "Anyone with the link" read-only sharing, revoke permissions via Drive Permissions API v3, and list/resolve pending Drive access requests (`accessproposals.list` / `accessproposals.resolve`) directly in `ShareSheet`.
- **Stateless hash invite links ([`src/drive/shareUtils.ts`](../src/drive/shareUtils.ts))**: Encode share metadata (`folderId`, `scope` = `book` | `library`, `name`, `role`) into `#/join?...` hash URLs compatible with static GitHub Pages subpath hosting, copyable to clipboard or shareable via the Web Share API.
- **Guided Join, Optional Google Picker & Native Drive Request Access handoff ([`src/drive/googlePicker.ts`](../src/drive/googlePicker.ts), [`src/components/JoinShareModal.tsx`](../src/components/JoinShareModal.tsx))**: With `drive` scope, already-shared folders resolve immediately on first join with zero Picker prompt. When joining returns `403`/`404` (e.g., recipient has not yet been granted Drive permission), `JoinShareModal` guides the recipient through (1) an explicit **Request Access in Google Drive** link opening `https://drive.google.com/drive/folders/{folderId}` paired with an in-modal retry button once approved, and (2) an optional Google Picker folder browser fallback.
- **Explicit Opt-In Sharing of Pre-Existing Personal Books ([`src/drive/syncService.ts`](../src/drive/syncService.ts), [`src/components/JoinShareModal.tsx`](../src/components/JoinShareModal.tsx), [`src/views/settings/DriveSyncSettingsSection.tsx`](../src/views/settings/DriveSyncSettingsSection.tsx))**: When joining a writable (`writer`) shared library while the device already holds personal books (`isShared === false`, `accessRole !== 'reader'`), StoryTape explicitly asks whether to share/copy those existing books into the shared library folder (`shareLocalBooksIntoSharedLibrary`, using server-side `files.copy` or resumable upload from local IndexedDB into the shared root while leaving any original personal Drive backup untouched). If the user declines, `syncAllWithDrive` never silently pushes unshared personal books (`isShared === false`) into the shared library; an in-Settings **Share Personal Books** action lets them opt in anytime later.
- **Quick single-chapter sharing**: Support native Web Share API (`navigator.share({ files })` with download fallback) so families can also send individual chapters directly over messaging apps without requiring Google Drive sign-in.
- **Cross-library Pull-Mirrored Book Import ([`src/drive/syncService.ts`](../src/drive/syncService.ts), [`src/drive/driveClient.ts`](../src/drive/driveClient.ts))**: When a user joins a read-only (`reader`) single-book share into a writable personal or family library, StoryTape defaults to **Import Copy to My Library**:
  - Copies cover art and chapter audio files into a real subfolder of the recipient's library root via server-side `files.copy` (automatically falling back to download + resumable upload if server-side copy fails), assigning fresh local `project.id` / `recording.id` keys paired with `sourceRecordingId` for collision-free delta matching.
  - Persists `importedFrom` (`folderId`, `sourceTitle`, `sourceProjectId`, `importedByEmail`, `importedAt`, `lastMirrorSyncAt`, `sourceUnavailable`) inside `project.json` so family co-narrators sharing the recipient's library automatically see and play the imported book with zero extra invites.
  - On subsequent syncs by the importer, checks `importedFrom.folderId` and mirrors only new/updated chapters and upstream chapter tombstones into the recipient's copied folder; non-importer family members silently skip upstream mirroring.

## System Invariants
1. **Recursive shared-folder access without a backend**: Rely on `https://www.googleapis.com/auth/drive` ([ADR-05](./ADR-05-client-side-drive-oauth-and-conflict-safe-sync.md)) for recursive folder visibility, and Drive's native folder UI for unprivileged users requesting access.
2. **Invite links remain stateless and subpath-safe** (`#/join?...`), and automatically clear `#/join` from the URL hash after joining or dismissing so reloads do not re-trigger the join modal.
3. **Graceful degradation for non-approvers**: `listAccessProposals` treats `403`/`404` responses as an empty list so non-owner collaborators never encounter errors in `ShareSheet`.
4. **No silent leakage of pre-existing personal books**: In shared library mode, `syncAllWithDrive` must never push unshared personal books (`isShared === false`) into the shared root unless the user explicitly opts in via the join prompt or Settings action.
5. **Upstream source non-interference & survival on revocation**: Pull-mirrored imports must never issue write, rename, or delete requests against `importedFrom.folderId`; if `importedFrom.folderId` returns `403`/`404`, sync must preserve the copied book intact and mark `sourceUnavailable: true` rather than deleting copied chapters or failing overall library sync.
6. **Non-importer family silence**: Family members syncing a shared library containing a book imported by another account (`importedByEmail` mismatch or `403`/`404` on upstream) must silently skip upstream mirroring and serve the real copied files directly.

## Consequences & Trade-offs
- **Pros:** Both family partners immediately see each other's books and chapters recursively with zero Picker walls, existing personal recordings are cleanly shared into the family folder on explicit user consent (and never silently leaked), zero backend invite broker, and cross-library imports automatically propagate to spouses/family members.
- **Cons:** First-time sign-in requires accepting Google's `drive` scope consent screen (including unverified-app confirmation for family deployments without CASA verification), and imported copies consume Drive quota in the recipient's library.
