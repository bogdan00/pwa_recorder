# ADR-06: Multi-User Shared Folder Unlock via Google Picker & Hash Invite Links

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related CUJs:** [CUJ-09](../cuj/CUJ-09-multi-user-sharing.md)

## Context
Under Google Drive's narrow `drive.file` OAuth scope ([ADR-05](./ADR-05-client-side-drive-oauth-and-conflict-safe-sync.md)), an app can only access files and folders that *the app itself created for the signed-in user* or that *the user explicitly selects via Google Picker*. When Parent A shares a StoryTape book or family library folder with Parent B or a grandparent, Parent B's StoryTape instance receives a `404` from Drive REST API v3 if it queries the shared folder ID directly—even when Parent B already has Google Drive permission on that folder.

## Decision
Keep the narrow `drive.file` scope (avoiding sensitive full-Drive verification) and build an end-to-end guided sharing & unlock flow without a backend:
- **In-app Drive Permissions & Pending Access Requests management ([`src/components/ShareSheet.tsx`](../src/components/ShareSheet.tsx), [`src/drive/driveClient.ts`](../src/drive/driveClient.ts))**: Allow hosts to invite collaborators by email (`writer` for Co-Narrators, `reader` for Listeners), toggle "Anyone with the link" read-only sharing, revoke permissions via Drive Permissions API v3, and list/resolve pending Drive access requests (`accessproposals.list` / `accessproposals.resolve`, both supported under `drive.file`) directly in `ShareSheet`.
- **Stateless hash invite links ([`src/drive/shareUtils.ts`](../src/drive/shareUtils.ts))**: Encode share metadata (`folder`, `scope` = `book` | `library`, `title`, `role`) into `#/join?...` hash URLs compatible with static GitHub Pages subpath hosting, copyable to clipboard or shareable via the Web Share API.
- **Lazy-loaded Google Picker unlock & native Drive Request Access handoff ([`src/drive/googlePicker.ts`](../src/drive/googlePicker.ts), [`src/components/JoinShareModal.tsx`](../src/components/JoinShareModal.tsx))**: Because Google Drive API v3 does not support creating access proposals programmatically (and returns `404` under `drive.file` for both unshared and unpicked folders), when joining returns `404`, `JoinShareModal` guides the recipient through both (1) 1-tap Google Picker folder selection for already-shared folders and (2) an explicit **Request Access in Google Drive** link opening `https://drive.google.com/drive/folders/{folderId}` so Google's native *"Request access"* UI notifies the owner, paired with an in-modal retry button once approved.
- **Quick single-chapter sharing**: Support native Web Share API (`navigator.share({ files })` with download fallback) so families can also send individual chapters directly over messaging apps without requiring Google Drive sign-in.
- **Cross-library Pull-Mirrored Book Import ([`src/drive/syncService.ts`](../src/drive/syncService.ts), [`src/drive/driveClient.ts`](../src/drive/driveClient.ts))**: Because Google Drive does not propagate folder permissions or `drive.file` Picker grants across external shortcuts, when a user joins a read-only (`reader`) single-book share into a writable personal or family library, StoryTape defaults to **Import Copy to My Library**:
  - Copies cover art and chapter audio files into a real subfolder of the recipient's library root via server-side `files.copy` (automatically falling back to download + resumable upload if server-side copy fails), assigning fresh local `project.id` / `recording.id` keys paired with `sourceRecordingId` for collision-free delta matching.
  - Persists `importedFrom` (`folderId`, `sourceTitle`, `sourceProjectId`, `importedByEmail`, `importedAt`, `lastMirrorSyncAt`, `sourceUnavailable`) inside `project.json` so family co-narrators sharing the recipient's library automatically see and play the imported book with zero extra invites or Google Picker prompts.
  - On subsequent syncs by the importer, checks `importedFrom.folderId` and mirrors only new/updated chapters and upstream chapter tombstones into the recipient's copied folder; non-importer family members silently skip upstream mirroring.

## System Invariants
1. **Never escalate beyond `drive.file` scope** to make shared folders, access proposal approvals, or cross-library book imports work; rely on Google Picker folder selection for explicit user consent and Drive's native folder UI for unprivileged users requesting access.
2. **Invite links remain stateless and subpath-safe** (`#/join?...`), and automatically clear `#/join` from the URL hash after joining or dismissing so reloads do not re-trigger the join modal.
3. **Graceful degradation for non-approvers**: `listAccessProposals` treats `403`/`404` responses as an empty list so non-owner collaborators never encounter errors in `ShareSheet`.
4. **Graceful non-Picker fallback**: Direct folder URL/ID paste in Settings remains supported when permissions are already unlocked.
5. **Upstream source non-interference & survival on revocation**: Pull-mirrored imports must never issue write, rename, or delete requests against `importedFrom.folderId`; if `importedFrom.folderId` returns `403`/`404`, sync must preserve the copied book intact and mark `sourceUnavailable: true` rather than deleting copied chapters or failing overall library sync.
6. **Non-importer family silence**: Family members syncing a shared library containing a book imported by another account (`importedByEmail` mismatch or `403`/`404` on upstream) must silently skip upstream mirroring and serve the real copied files directly.

## Consequences & Trade-offs
- **Pros:** Preserves least-privilege OAuth posture, zero backend invite broker, works for both single shared books and whole shared family libraries, enables separate personal/family libraries to exchange finished stories that automatically propagate to spouses/family members with zero extra Picker prompts, and survives upstream unsharing or deletion cleanly.
- **Cons:** First-time recipients of a shared Drive folder perform one extra tap in Google Picker to unlock `drive.file` access, uninvited recipients must tap Google Drive's native *Request access* button once in a browser tab before retrying, and imported copies consume Drive quota in the recipient's library (negligible for compressed audiobook audio) and mirror upstream updates when the importer opens/syncs the app.
